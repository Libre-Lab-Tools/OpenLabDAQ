OpenLabDAQ

OpenLabDAQ connects laboratory instruments, displays live values, plots recent measurements, and saves synchronized data.

Quick Start

1. Configure the DAQ

  1. Make sure acquisition is stopped.
  2. Click Configuration.
  3. Enable the sensors you want to use.
  4. Select or enter the COM port for each sensor.
  5. Optionally enter a GUI nickname, such as Chamber Temperature.
  6. Select a plot scale for each sensor: Linear or Logarithmic.
  7. Select the acquisition period and saving directory.
  8. Click Save.
A nickname changes only the sensor and plot labels shown in the GUI. CSV headers keep the official sensor name. Plot scale changes only how values are displayed; History and CSV files keep the original numerical values.
Use a logarithmic plot for measurements that span several orders of magnitude, such as high-vacuum pressure. Logarithmic plots can display only positive values. Zero and negative values are omitted from the plot but are not changed in History or exported data.

2. Start Acquisition

Click STOPPED. OpenLabDAQ connects the enabled sensors and then changes the button to RUNNING.

Current values appear on the left and plots update automatically.

3. Understand Sensor Status

  • Green dot: the sensor returned a valid reading. Short glitches that succeed during an immediate retry remain green.
  • Red dot: all immediate read attempts failed and OpenLabDAQ marked the sensor unavailable. The last valid value may remain visible while new records contain a blank value.
  • Gray dot: acquisition is stopped.

OpenLabDAQ tries each sensor reading up to three times before declaring a communication failure. If an immediate retry succeeds, the fresh value is recorded normally and no event is created. If all attempts fail, the sensor produces blank CSV values while the other sensors continue. OpenLabDAQ then retries the connection approximately once per minute.

4. View Recent Events

The Recent Events panel shows the newest events from the current acquisition session, including persistent sensor communication failures and recoveries. A single failed read that succeeds during an immediate retry is treated as a recovered glitch and is not added to Recent Events. The panel remains available whether or not CSV logging is active.

Recent Events is temporary and is cleared when a new acquisition session begins. When logging is active, the same automatic events are also written to the permanent logbook.

5. View and Export History

  • Use the History selector to display the latest 5 minutes, 20 minutes, 2 hours, 6 hours, 1 day, or 3 days.
  • Click the star beside a plot to pin it to the top.
  • Scroll to view additional plots.
  • The vertical plot range adjusts automatically to visible data.
  • Click Export Data to save all sensors in the currently displayed time range to a CSV file.
Export Data works even when normal logging is off, as long as the measurements are still available in History.

6. Start Logging

  1. Start acquisition.
  2. Click LOAD.
  3. Enter optional run information such as experiment, sample, gas, operator, and general notes.
  4. Click Start Logging.

OpenLabDAQ creates two matching files in the configured saving directory: 

2026-07-17_12-58-00.csv
2026-07-17_12-58-00_logbook.txt

The CSV contains sensor measurements. The logbook contains run information and timestamped events.

7. Add a Manual Event

While logging is active, click ADD EVENT.

OpenLabDAQ captures the event timestamp immediately when the dialog opens. You may then take time to enter a short event and an optional comment without changing the recorded event time.

Examples include:

  • Gas changed
  • Valve opened
  • Heating started
  • Sample inserted

The event appears in Recent Events and is written to the active logbook.

8. Stop Logging or Acquisition

Click LOGGING to stop saving data and close the logbook.

Click RUNNING to stop acquisition and disconnect all sensors. Stopping acquisition also stops logging.

History, Recent Events, and Permanent Files

History is temporary and is stored in computer memory. OpenLabDAQ keeps up to 72 hours during one continuous acquisition session.

Recent Events is also temporary. It provides operational awareness during the current session but does not replace the permanent logbook.

History resets when a new DAQ session begins or when OpenLabDAQ closes. Permanent sensor data is created only while the button displays LOGGING, or when you manually use Export Data.

Troubleshooting

Could not open COM port

  • Verify that the instrument is powered.
  • Verify that the USB or serial cable is connected.
  • Check that the correct COM port is selected.
  • Close other software that may already be using the port.

The Configuration button is disabled

Configuration cannot be changed while acquisition is running. Stop acquisition first.

No CSV file is being created

Confirm that acquisition is running and that the logging button displays LOGGING.

ADD EVENT is disabled

Manual events can be added only while CSV logging and the matching logbook are active. Automatic sensor events still appear in Recent Events when logging is off.

A sensor dot is red

All immediate read attempts failed. Check the instrument power, cable, COM port, and communication settings. OpenLabDAQ continues reading other sensors, records blank values for the failed sensor, and attempts to reconnect it approximately once per minute.

A logarithmic plot is empty

Logarithmic plots require positive values. Confirm that the sensor is returning positive measurements and that the selected plot scale is appropriate for the instrument's operating range.

Export Data reports no data

The selected History range does not contain measurements. Start acquisition and wait for data to appear.

A sensor does not connect at startup

Check its COM port, cable, power, and instrument communication settings. Initial connection failures stop startup so the configuration can be corrected before acquisition begins.

History and Recent Events are not permanent. Use normal logging or Export Data when measurements and events must be preserved.
